This file records development snapshots. No public release has been published.

## Unreleased — local M10 documentation and packaging snapshot

- Added user/developer documentation for the OpenCode 1.19.0 compatibility baseline, Managed database isolation, verification boundaries, and current milestone state.
- Prepared a local VSIX for inspection from the existing provisional manifest identity. Publisher/Marketplace ownership remains unverified; this is not a release or publication claim.
- Added managed-server lease self-healing on connect: when the recorded owner extension host is dead, a fresh host adopts a healthy orphaned managed server (rewrites the lease with its own nonce/hostPid, keeps processPid/serverUrl), kills an unhealthy orphaned one through the bounded terminateProcess hook (taskkill /T /F tree on win32) before unlinking, reclaims leases left incomplete by a dead host, and clears a stranded `.lease.reaper` guard by reading the guard's recorded owner. A live owner host keeps the exact existing busy error; unknown process/endpoint status and unparseable lease records fail closed. Adopted-process lifecycle (`start()` returns the adopted URL without spawning; `isRunning()` reports held adoption; `dispose()` does graceful SDK dispose then bounded PID-verified taskkill/SIGTERM→SIGKILL after `lease.ownsProcess`) mirrors the spawned lifecycle. The connection layer is unchanged; existing managed-start and lease-conflict connection tests pin both outcomes. Deterministic verification: focused lease/server/connection suites passed (3 files, 51 tests + 1 gated real-CLI smoke skipped), typecheck clean, build built in 214ms; no live OpenCode runtime was exercised. Review correction: orphan/adopted termination happens only after the live PID's image is verified as the extension's OpenCode executable (tasklist win32 / procfs POSIX); unverifiable identity fails closed.
- Hardened the default POSIX orphan-identity check (escalated review follow-up): instead of matching the "opencode" substring inside `/proc/<pid>/cmdline` — which an unrelated process holding a recycled PID, e.g. an editor opening an opencode-named file, could satisfy — the verifier now requires the canonical `/proc/<pid>/exe` target (resolved via realpath) to equal exactly the opencode executable that realpath resolves from an absolute PATH entry. Unreadable procfs or PATH, a missing command, and relative-only PATH entries fail closed (no signal sent, no lease release); there is no fallback discovery, shell command, or cmdline consultation. The Windows verifier, the injected `verifyOrphanProcessImage` hook, and SIGTERM→SIGKILL sequencing are unchanged. Deterministic verification: focused lease/server/connection suites passed (3 files, 64 tests + 1 gated real-CLI smoke skipped; the same suites on an unmodified base-commit copy passed 59 + 1 skipped), typecheck clean; no live OpenCode runtime and no real signal was exercised.
- Recorded user-observed Managed runtime behavior separately from agent-run mocked verification.
- Documented the remaining M4 equal-timestamp history-refresh ordering defect and outstanding manual/provider-dependent checks.
